# 流浪猫识别与走失猫寻回平台：开发规格

版本：2026-10-26。基础仓库：`keepfight1/search-image-by-image`，审阅提交 `9d2b33b7a2c26dd3f49b01405e5abeaa204defc2`。本文可直接作为 Codex 的分阶段执行依据。

## 1. 目标与边界

目标是让发现者发布目击猫信息，让主人发布走失猫信息；系统在两类记录之间双向检索，按图片相似度、地点、时间和人工描述提供**疑似同一只猫**的候选，并让双方安全联系。系统不能仅凭品种或毛色宣称识别出个体，也不能把余弦相似度展示成“找回概率”。

首版只支持猫。记录类型为 `lost`（主人走失）与 `sighting`（发现者目击），一次搜索仅查相反类型。允许发现者不知道品种、毛色或精确时间；字段可选且要有“未知”。不自动认领、不自动公开联系电话、不依赖用户当前定位代替事发地点。管理员负责处理虚假、重复和不适宜内容。

首版交付：可发布和编辑记录、上传 1–5 张图、查看疑似匹配、扩大搜索范围、发送站内联系请求、关闭已找回记录、基本审核与举报、完整的效果评测报告。首页提供“我丢了猫”“我发现猫”两个清晰入口、搜索列表、详情页和个人发布管理。

## 2. 现有仓库审计与处理决定

| 现状 | 证据 | 开发决定 |

## 3. 用户流程和字段

### 3.1 发现者发布

填写：发现时间 `observed_at`、发现地点（城市/区县/地点描述/可选坐标）、1–5 张猫图、毛色、花纹、品种（均可选或未知）、体型、显著特征（剪耳、项圈、疤痕等）、猫当前状态（仅目击/暂时收留/已送机构）、补充说明。照片最好引导上传正脸、左右侧面、全身，要求同一只猫；多猫同框时让用户选取目标。提交后自动搜索现有走失记录并保存匹配任务。目击时间应允许“不确定”，存时间范围或精度，不能伪造到分钟。

### 3.2 主人发布

填写：最后见到的时间 `last_seen_at`、最后地点、1–5 张清晰猫图、毛色/花纹/品种（允许未知）、性别/绝育/体型（可选）、显著特征和说明。提交后搜索目击库。可编辑、补图、标记找回或撤回；新增目击也应触发反向匹配及通知。

### 3.3 搜索与联系

先展示候选卡片：猫图、公开的模糊地点、时间、显著特征、匹配解释（“图片相似”“距离近”等）和风险提示。允许调整半径、日期、毛色、品种；默认不要因品种未知、标注错误或跨区而彻底排除候选。用户点“可能是我的猫”后发送站内联系请求，由对方选择回复；管理员可处理举报。公开页面最多显示区县或由用户确认的模糊地点，不公开精确坐标和电话。宠物归属由双方通过更多照片、项圈信息、芯片/领养证明等线下核实。

## 4. 数据模型与存储

生产版建议 PostgreSQL + `pgvector` + 私有对象存储（开发环境可用本地文件或 MinIO）。PostgreSQL 管业务与筛选，`pgvector` 存同版本图像向量；原图放对象存储，不放数据库。首批数据很少时使用带条件过滤的**精确余弦检索**，避免过早引入近似索引造成漏召回。数据量和延迟达到门槛后才试 HNSW，并与精确结果比较 Recall@K。

建议的表：

| 表 | 关键字段 |
| --- | --- |
| `users` | `id, login_identifier, role, created_at, disabled_at`；敏感联系信息单独受控存放。 |
| `reports` | `id, owner_user_id, type, status, city_code, district_code, location_text_public, location_lat_private, location_lng_private, event_time_start, event_time_end, event_timezone, coat_colors[], pattern, breed, breed_confidence/source, distinctive_marks, cat_state, description, created_at, updated_at, deleted_at`。 |
| `report_images` | `id, report_id, storage_key, thumbnail_key, sha256, phash, width, height, primary, upload_order, created_at`。 |
| `image_embeddings` | `image_id, model_version, crop_version, vector(512), quality, detection_box, state, created_at`；唯一键 `(image_id, model_version, crop_version)`。 |
| `match_candidates` | `lost_report_id, sighting_report_id, model_version, image_score, final_rank_score, evidence_json, state, created_at, updated_at`；去重唯一键覆盖两记录和模型版本。 |
| `contact_requests` | `requester_id, target_report_id, message, state, created_at`；只在私有接口返回。 |
| `moderation_events` | 审核、举报、封禁与操作记录。 |

所有时间在后端转为 UTC 保存，并记录原时区；界面按用户时区显示。地点保存用户确认的事发位置，浏览器当前定位仅作填表建议。图片上传应校验真实格式、大小、像素上限、解压炸弹与 EXIF 方向；生成去 EXIF 的公开图和缩略图；避免孤儿文件。`report` 状态至少包括 `active/resolved/withdrawn/hidden`，仅 `active` 参与检索。数据迁移通过 Alembic 执行，现有 SQLite 数据先备份，再写一次性迁移脚本及映射报告。

## 5. 图像识别方案

### 5.1 先做可重复的模型选型

候选 A：仓库 PetReID（需取得实际 `best.pt`，确认训练授权及预处理）。候选 B：`open-noodle/pet-recognition-base` 的猫个体向量模型，ONNX、512 维归一化，官方模型卡报告其 Cat Individual Images 测试集 Top-1 约 0.916；该数字是模型自己的数据集协议，不可与本仓库的 0.663 直接比较，也不保证街景效果。先用本项目**同一份冻结测试集**比较二者；如果 A 不可用或 B 在真实场景显著更好，就用 B。两个模型虽同为 512 维，向量空间也不兼容，切换时必须全部重新提取、重建索引、重标阈值。不要把 PetFace 模型直接用于公众平台：其官方仓库限定非商业研究，且数据需申请。

图像处理：解码与方向校正 → 检测猫并提取主体框 → 用户必要时确认目标猫 → 保留原图和主体裁剪 → 每张图提取主体向量；在验证集上试正脸/全身双路特征，如果收益显著再加入。检测失败或图片过暗/过糊时提示换图，不应静默当成“无匹配”。同图或近重复图只做发布去重，不把重复上传当两个独立线索。

### 5.2 检索与排序

1. 结构化筛选仅硬性限制 `type=opposite`、`status=active` 和已成功提取向量；猫为唯一物种。地点默认从确认的事发地点向外搜索，首圈同区或 10 km，候选不足时逐级扩大同市及周边市；展示当前搜索范围。时间使用可配置窗口，考虑走失早于目击的合理顺序，但模糊时间、未填时间只作降权或放宽，不作绝对排除。
2. 第一阶段以每张查询图对候选图求余弦相似度，取足够大的候选池（例如每图 Top 100，参数可调）；多个查询图取最佳质量加权结果，按**报告 ID**聚合，避免同一报告占满 Top 5。保留原始图片分数供调试。
3. 第二阶段在冻结验证集上学习或网格搜索轻量重排：主体图像分数为主，距离、时间、毛色/花纹、显著特征为辅。品种只能弱加分；“未知”不得惩罚。设置图像分数下限和候选展示策略时，必须测真实同猫召回与误报，不能照搬旧阈值 0.72/0.45。
4. 结果显示“高/中/低优先级候选”及依据，不把 `score × 100` 写为准确率。若无结果，提供手动扩大范围与保存订阅；不要只返回“暂无可靠线索”后终止。
5. 每次发布、补图、修改地点或重新建模时异步计算向量并增量匹配。任务有状态、重试、幂等键和失败提示；检索接口不得在 Web 请求中同步提取所有图库图像特征。

`pgvector` 的 HNSW 对带条件过滤查询可能在索引扫描后才过滤，窄条件下会返回不足 K 个；启用近似索引时测试不同条件的召回，并视情况使用精确检索、分区/部分索引或迭代扫描。向量服务必须记录 `model_version`，严禁跨版本混查。

## 6. API 与页面契约

建议以 `/api/v2` 建立新契约，避免直接破坏旧演示接口。统一 JSON 错误格式、分页和鉴权；OpenAPI 作为前后端共享契约。

| 接口 | 作用与要点 |
| --- | --- |
| `POST /api/v2/images` | 上传图片，返回临时 `image_id`、缩略图和质量提示；需用户身份、限流、临时文件过期清理。 |
| `POST /api/v2/reports` | 创建 `lost/sighting`；校验图片归属、时间与地点；返回报告 ID 和匹配任务状态。 |
| `PATCH /api/v2/reports/{id}` | 仅发布者或管理员编辑、补图、关闭；更新后触发重检索。 |
| `GET /api/v2/reports` | 公开列表，支持城市、时间、颜色、类型等过滤与游标分页；只返回脱敏字段。 |
| `GET /api/v2/reports/{id}` | 公开详情，公开坐标按用户授权模糊化。 |
| `POST /api/v2/reports/{id}/matches` | 手动重新检索或扩大范围，返回任务 ID。 |
| `GET /api/v2/reports/{id}/matches` | 返回按报告聚合的候选、依据、范围和模型版本，不含私人联系方式。 |
| `POST /api/v2/contact-requests` | 对候选发送站内联系请求，防重复、限流。 |
| `GET /api/v2/me/reports`、`GET /api/v2/me/contact-requests` | 用户管理自己的发布与联系。 |
| `POST /api/v2/reports/{id}/report` | 举报内容或冒领；管理员接口审核。 |

页面至少有：首页/说明、双入口发布向导、按条件搜索、匹配结果、报告详情、我的发布、联系请求、管理员审核。移动端优先；发布中断可保存草稿；地图失败可手填行政区与地点；错误信息指出具体字段。单图、多图、无坐标、未知品种、检测失败、空结果、后台任务失败都要有明确状态。

## 7. 数据集、授权与评测

数据分三层管理，不混用身份标签和实际发布记录：

### 7.1 替换当前 PetFinder 数据的具体推荐

**第一选择：Cat Individual Images**。它是目前最贴近“同一只猫有多张不同照片”的公开数据。原始版本的研究资料记载约 518 只猫、13,536 张图；WildlifeReID-10k 清洗版本统计为 509 只猫、13,021 张图，两者不是同一个清洗口径。文件按个体组织，可形成查询图和图库图；同时存在多猫同框、背景较强、同一场景连拍等噪声，导入前必须人工抽检、猫主体裁剪和近重复图清理。它**没有完整可靠的品种、毛色、走失地点和时间标签**，这些字段只能由人工补标或在真实平台数据中形成，不能凭文件夹名臆造。数据页：[Kaggle Cat Individual Images](https://www.kaggle.com/datasets/timost1234/cat-individuals)。

**标签说明**：Cat Individual Images 的个体身份标签体现在“每只猫一个目录”的分组中，导入时可把目录名转为 `cat_id`；它不是带有每张图的品种、毛色、地点等属性标签 CSV 的数据集。若项目要求“身份 + 品种 + 毛色”全部原生标注，Cat Individual Images 单独使用不满足要求，需另行人工标注属性，或在获得授权后使用含属性注释的 PetFace 猫子集。导入前还要抽样核对每个目录是否确实只有同一只猫。

**第二选择：PetFace 猫子集**。这是规模更大的个体识别研究数据，有猫身份及相关属性注释，适合非商业课程研究；但官方明确其数据、代码和预训练模型仅供非商业研究，而且下载需申请。只有拿到授权并确认本项目用途符合其条款后才能用于训练。数据与代码：[PetFace 官方仓库](https://github.com/mapooon/PetFace)。

**第三选择：Dryad 公开的野外猫相机陷阱数据**。相比家庭宠物照更接近室外场景，相关研究在其中选用了 10 只猫、1,644 张图做个体实验；数量和拍摄方式与手机寻猫仍有差异，适合作为单独的跨场景测试集或补充训练集，不适合作为唯一训练来源。使用前应下载并核查 `raw_data.zip`、README 中个体编号的映射和许可。[Dryad 原始数据](https://datadryad.org/dataset/doi:10.5061/dryad.69p8cz95w)、[相关研究](https://researchportal.murdoch.edu.au/esploro/outputs/journalArticle/Body-part-based-individual-feral-cat-identification-from/991005787483207891)。

**辅助数据：Oxford-IIIT Pet** 有品种、头部框和主体分割标注，适合训练猫检测/裁剪与品种辅助识别，不能充当“同一只猫”数据。[官方页面](https://www.robots.ox.ac.uk/~vgg/data/pets/)。北大校园猫项目和 MeowID 可参考检测、训练、路由与界面做法，但它们公开页面未证明完整训练数据可直接下载并用于本项目，因此暂不作为数据替换方案。[北大猫咪识别器](https://github.com/Sherlock-LXL/pku-cat-recognition)、[MeowID](https://github.com/RicePasteM/MeowID)。

数据替换的可执行选择是：课程原型用 **Cat Individual Images 的按猫身份数据**替换现有 PetFinder 训练/测试主体，同时用 Oxford 数据辅助猫主体定位；若得到 PetFace 许可再增补。最终效果要靠平台真实授权样本单独验收，特别是主人旧照与发现者街拍的跨场景配对。无论选择哪个集，**训练数据不能被当成平台的真实“已发现流浪猫库”**，也不能把测试集猫照片伪装成真实寻猫线索。

导入脚本统一生成 `image_id, cat_id, image_path, source, license, split, capture_session, bbox, quality, coat_color, pattern, breed`。其中 `cat_id` 是身份标签；品种/毛色允许为空并标记标注来源。按 `cat_id` 分割训练/验证/测试，且同一拍摄会话不得跨查询/图库；保存来源文件与校验和。对已被预训练模型使用的数据，另外保留未见过的真实猫测试集，避免重复使用导致效果高估。

| 来源 | 用途 | 注意 |
| --- | --- | --- |
| 现有 PetFinder 子集 | 保留为历史基线、代码回归测试 | 官方说明档案可能涉及多只动物，且许可证为竞赛规则；抽样核验身份并核对再利用权限。脚本生成的城市、坐标、时间只作模拟，绝不称为真实目击。 |
| Cat Individual Images | 猫个体识别训练/独立测试候选 | 有同猫多图；核实数据页许可证、保留来源与署名，按猫个体切分且与预训练模型训练集去重。若候选 B 已使用该集训练，不能把其公开测试指标当本项目独立验证。 |
| Oxford-IIIT Pet | 猫/宠物检测、裁剪、品种辅助任务 | 有品种、头部 ROI、分割标注；**没有同一只猫身份标签**，不得用于个体识别 Top-K 测试。核对图片再利用许可。 |
| 本平台自愿授权真实样本 | 最终场景验收与后续微调 | 需用户授权、去标识、删除机制；把同猫不同时间地点和相似毛色的不同猫都纳入。 |
| PetFace | 研究对照候选 | 官方限定非商业研究且申请访问，未获授权不得部署或混入公开权重。 |

冻结测试集须以 `cat_id` 隔离训练/验证/测试；同图、连拍、近重复图不可跨查询和图库；测试图库需模拟“主人照片 vs 街拍目击”的域差异。每个测试版本明确图库猫数、每猫图数、正样本查询数、**图库中不存在同猫的负样本数**、图像质量分层、地点/时间字段真实或合成。既测照片级 Top-1/Top-5，也测**报告级 Recall@5/10**、mAP、无匹配查询误提示率/FAR、精确率、P95 端到端耗时；分层看黑猫、橘猫、花猫、夜间、侧脸、遮挡、模糊、跨区。

建议验收门槛（项目目标，非现有成绩）：在冻结的真实或授权外部猫测试集上，报告级 Recall@5 ≥ 0.85、无同猫时“高优先级”误提示率 ≤ 0.05、P95 检索 ≤ 3 秒（不含首次异步建模）；若样本不足或未达标，必须显示真实结果和限制，不能改写数字。上线前另以人工标注的至少 100 个正例、100 个负例试点验证阈值；样本量越小，置信区间越宽，应报告 95% 置信区间。不要用训练集或旧模拟位置数据标定业务阈值。

## 8. 分阶段 Codex 执行清单

### 阶段 0：固定基线与数据审计

在新分支上运行现有后端测试和前端构建，记录实际成功/失败；生成文件树、依赖清单、数据库结构及旧 API 快照。核验 `dataset/` 图片来源、许可、身份标注和重复图；记录 `best.pt` 缺失并决定可取得的权重。交付 `docs/audit.md`、`docs/data_sources.md` 和不提交数据/密钥的 `.gitignore`。验收：任何人按 README 能复现现有演示，并看懂哪些数据是合成的。

### 阶段 1：业务数据与安全底座

引入 PostgreSQL、Alembic、对象存储适配层、用户身份及权限；迁移旧数据模型为 `reports/images/embeddings`，增删改查和状态流转完整。完成图片安全处理、公开字段脱敏、联系人站内请求与举报。验收：发布者只能改自己的记录；未授权用户拿不到电话或精确坐标；关闭记录不进入检索；迁移可回滚、重复执行不损坏数据。

### 阶段 2：可用前端与双向闭环

重构 Vue 页面与 API 客户端；双向发布、地图/手填地点、1–5 图预览、搜索和个人中心。修复城市硬编码、定位写错事件坐标、上传位置强制填写。验收：在空库、同区、跨区、无坐标、多图、关闭记录情形下都能完成真实用户操作；手机宽度可用。

### 阶段 3：模型与匹配

实现猫检测/裁剪、图像质量提示、模型适配器（PetReID 与 pet-recognition-base）、批量重建脚本、版本化向量。先比较同一冻结测试集，再选模型；实现多图向量检索、同报告聚合、地理/时间逐级扩展与重排。验收：模型缺失不会回退到 `lightweight`；同一猫多图只占一个候选；旧版本向量不参与新版本检索；提交正式评测 JSON 与错误案例集。

### 阶段 4：异步增量匹配与上线准备

接入任务队列（如 Redis + worker）处理上传、向量提取、匹配和通知；统一 Docker Compose 启动前端、API、数据库、对象存储和 worker。补充备份恢复、日志、任务失败告警、限流与管理员审核。验收：新目击能重新匹配已有走失记录；worker 重启后任务可恢复；从全新环境一条命令启动并完成双向演示。

每阶段都提交：代码、迁移、必要的接口/业务测试、README 运行命令、真实测试输出和已知限制。不要为了让指标通过而调测试集。所有关键参数（模型哈希、裁剪版本、阈值、搜索半径、时间窗口）写入配置与评测报告。
