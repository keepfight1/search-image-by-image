# 流浪猫识别平台：课堂展示评测报告

**测试对象**：RF-DETR Nano 猫检测 + `pet-recognition-base` 个体向量检索，阈值固定为 `0.45`。评测使用两套固定离线协议，分别衡量最初 50 只猫图库的接通情况和外部街猫图片的跨数据源表现。所有数字由脚本生成，不按成功与否筛选样本。若后来把 HelloStreetCat 的 20 只图库猫导入平台，这些数值仍是原协议的历史结果，不能直接当成扩容后混合图库的网页准确率。

## 数据来源与测试包

| 协议 | 图库 | 同猫查询 | 库外猫查询 | 解释 |
| --- | ---: | ---: | ---: | --- |
| A 原 50 猫图库快照 | Cat Individual Images 前 50 只猫，每只 2 图，共 100 图 | 每只 2 张未入库文件，共 100 图 | HelloStreetCat 10 只猫、每只正面/俯视各 1 图，共 20 图 | 检查最初 50 条样例走失线索的图像检索 |
| B 外部街猫图库 | HelloStreetCat 20 只猫，每只正面/俯视各 1 图，共 40 图 | 同 20 只猫每只另一张正面/俯视图，共 40 图 | 另 10 只猫，每只 2 图，共 20 图 | 检查另一来源、另一拍摄方式下的泛化与误候选 |

来源：[Cat Individual Images](https://www.kaggle.com/datasets/timost1234/cat-individuals)、[HelloStreetCat Individuals](https://www.kaggle.com/datasets/tobiastrein/heellostreetcat-individuals)。HelloStreetCat Kaggle API 元数据标记为 **CC BY-NC 4.0**，所以图片只存本机、用于非商业课堂演示。使用其第 3 版压缩包，实际有 68 个可识别身份目录，其中 49 个同时至少有两张正面、两张俯视图；本项目固定随机种子 `20261026` 抽取 30 个身份。来源路径与原图 SHA256 在本机 `dataset_cat50/testset/manifest.csv`（脚本也兼容原目录名 `teacher_testset/`）。数据集论文介绍其来源于街猫喂食站：[Trein 与 Garcia，2025](https://arxiv.org/abs/2501.02112)。

**重要区别**：识别模型[官方模型卡](https://huggingface.co/open-noodle/pet-recognition-base)说明其投影层训练用过 Cat Individual Images，因此协议 A 的同猫查询虽然没有进入当前网页图库，仍**不是模型训练独立测试**。协议 B 的来源未列入模型卡公开的投影训练数据，但不能证明通用骨干预训练完全没有接触过相关图片。

## 核心结果

| 指标 | A 原 50 猫图库快照 | B 外部街猫图库 |
| --- | ---: | ---: |
| Top‑1：正确猫排第 1，不加阈值 | **97/100 = 97.0%**，95% CI 91.6%–99.0% | **14/40 = 35.0%**，95% CI 22.1%–50.5% |
| Top‑5：正确猫进入前 5，不加阈值 | 100/100 = 100% | 26/40 = 65.0% |
| 阈值 0.45 下 Recall@1 | 94/100 = 94.0% | 12/40 = 30.0% |
| 阈值 0.45 下 Recall@5 | 96/100 = 96.0% | 21/40 = 52.5% |
| 库外猫出现至少一个过阈值候选（全部提交） | 0/20 = 0%，95% CI 0%–16.1% | 14/20 = 70.0%，95% CI 48.1%–85.5% |
| 库外误候选率（仅检测到猫的图） | 0/18 = 0% | 14/18 = 77.8% |
| 图库 / 同猫查询 / 库外查询检测失败 | 0 / 0 / 2 | 1 / 3 / 2 |
| 同猫正确身份得分中位数 | 0.8106 | 0.5273 |
| 库外猫最高得分中位数 | 0.2797 | 0.5837 |
| 单图检测+特征提取耗时中位数 / P95（本机最近一次） | 0.3683 / 0.3857 秒 | 0.3245 / 0.3549 秒 |

95% 置信区间使用 Wilson 二项区间。所有分母包含固定抽取的图片，检测失败不会被删掉；两组图库不同，库外误候选率不能简单当作同一个总体的对照实验。余弦相似分不是“同一只猫的概率”。耗时只测本机单图提取，不含网页传输与数据库查询，重复运行会波动。协议 B 中正面查询 Top‑1 为 **6/20**，俯视查询 Top‑1 为 **8/20**。阈值扫描和逐张预测见本机 `dataset_cat50/testset/teacher_report.md`、`predictions.csv`、`platform_predictions.csv`。原数据集的身份标签沿用目录名，未对每张图的个体身份作独立人工复核。

协议 B 的阈值诊断进一步说明取舍：阈值 `0.35` 时 Recall@1 为 **14/40**、库外误候选 **18/20**；当前 `0.45` 时分别为 **12/40** 和 **14/20**；提高到 `0.60` 后分别为 **10/40** 和 **8/20**。这些数值只是同一测试集上的诊断，不能反过来挑一个“最佳阈值”再把它当作独立测试成绩。

**结论**：系统能跑通“上传图片→检测猫→提取特征→在 50 条走失线索中排序”的流程；当前 50 猫图库的同源演示效果较好。外部街猫测试显示明显的跨场景性能下降和误候选问题，不能声称达到真实寻猫可用的准确率。下一步需要获得真实的“主人旧照↔街头手机照”授权样本，按个体与拍摄会话隔离，重新训练或选择更合适的识别模型，并在独立数据上标定阈值。

## 网页现场演示

本机图片包在 `dataset_cat50/platform_demo/`：`positive/` 有 10 张原 50 猫图库同猫照片，`negative/` 有 5 张库外猫照片；`manifest.csv` 写明身份和预期记录 ID，`observed_results.csv` 写明**原 50 猫图库快照**的离线实测名次及阈值结果。抽样固定且**没有只挑识别成功的图片**，因此包内也有真实失败案例。导入 HelloStreetCat 的 20 只猫后，网页搜索范围扩大，现场名次可能与此文件不同。

1. 打开平台的“匹配线索”，选择“我发现猫 · 查找走失线索”。
2. 上传 `positive/` 的任一图片，先把地点、日期和外观筛选留空；检查候选列表和 `manifest.csv` 中的预期记录。
3. 上传 `negative/` 的图片，观察是否误报。若误报出现，应如实解释“候选需要人工核实”。
4. 不要把样例线索的上海浦东地点和时间当成真实事件，也不要用这些演示字段筛选外部照片。

## 复现命令

在项目根目录执行；外部图片和运行结果均写入 `.gitignore` 已排除的 `dataset_cat50/`，不会推送到 GitHub。

```powershell
.\.venv\Scripts\python.exe scripts\prepare_teacher_testset.py
.\.venv\Scripts\python.exe scripts\evaluate_teacher_testset.py
.\.venv\Scripts\python.exe scripts\prepare_platform_demo.py
.\.venv\Scripts\python.exe scripts\evaluate_deployed_gallery.py
```

准备脚本检测到现有清单会停止，避免重抽样覆盖；重新评估可直接运行后两个 `evaluate` 脚本。评测代码见 [`prepare_teacher_testset.py`](../scripts/prepare_teacher_testset.py)、[`evaluate_teacher_testset.py`](../scripts/evaluate_teacher_testset.py) 和 [`evaluate_deployed_gallery.py`](../scripts/evaluate_deployed_gallery.py)。
