# 当前图库演示与测试流程

本说明对应本机全量索引后的检索状态：50 条 Cat Individual Images 发现样例、20 条 HelloStreetCat 发现样例、80 条 `dataset` 发现样例和 2 条用户发现线索，共 **152 条活跃发现线索、1,757 个可检索图片向量**；另有 2 条历史用户走失记录，浏览总数为 154。其中 Cat Individual Images 的 1,487 张目录照片有 **1,486 张**通过猫检测并进入检索；`dataset` 的 230 张 gallery 照片有 **229 张**进入检索。发布页只接收发现线索，丢猫用户在匹配页上传照片查询，查询本身不会公开发布。样例地点和时间来自演示元数据；研究样例的 `000` 开头号码只是模拟值。模型使用 RF-DETR Nano 检测猫、`pet-recognition-base` 提取向量，图片相似度阈值为 `0.45`。模型作者公开说明其识别投影层曾使用 Cat Individual Images 训练：[模型卡](https://huggingface.co/open-noodle/pet-recognition-base)。`dataset` 固定测试划分的结果另见 [dataset 猫图库评测报告](dataset图库评测报告.md)。

## 一、离线复测方法

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_current_platform.py
```

脚本从**当前数据库全部活跃发现线索**读取与现用模型版本一致的向量。查询时不填地点、日期、毛色、品种等筛选条件，逐只猫以最高图片相似分排序。因为 Cat Individual Images 的所有合格照片现已入库，测试 A 在排序时会排除查询照片自身的向量，避免同一文件与自身比对；这仍不能消除同场景连拍或模型训练数据重叠。测试图片固定如下：

| 查询组 | 来源与选择方式 | 张数 | 预期 |
| --- | --- | ---: | --- |
| A：Cat Individual Images 同猫照 | 前 50 只猫，每只固定取 2 张照片，评分时排除该照片自身 | 100 | 对应的 50 条样例中应有正确身份 |
| B：HelloStreetCat 同猫照 | 已导入的 20 只猫，每只另取正面、俯视各 1 张 | 40 | 对应的 20 条样例中应有正确身份 |
| C：HelloStreetCat 库外猫 | 未导入的另外 10 只猫，每只 2 张 | 20 | 不应出现过阈值候选 |

外部图库照片和查询照片是不同文件；外部图片清单、原始文件名和 SHA256 在本机 `dataset_cat50/testset/manifest.csv`（脚本也兼容目录名 `teacher_testset`）。抽样种子固定为 `20261026`，没有按匹配成功与否选图。检测失败计入总数。机器可读结果保存在本机未跟踪的 `dataset_cat50/testset/current_gallery_metrics.json`，逐图排序在 `current_gallery_predictions.csv`。运行测试不会向平台发布查询线索。

## 二、当前实测结果

以下结果来自本机当前图库，阈值固定为 `0.45`：

| 指标 | A：100 张同源查询 | B：40 张外部同猫查询 |
| --- | ---: | ---: |
| Top-1：正确线索排第一，不看阈值 | **98/100 = 98.0%** | **14/40 = 35.0%** |
| Top-5：正确线索进入前五，不看阈值 | 100/100 = 100% | 25/40 = 62.5% |
| Recall@1：正确线索第一且得分 ≥0.45 | 98/100 = 98.0% | 12/40 = 30.0% |
| Recall@5：正确线索前五且自身得分 ≥0.45 | 99/100 = 99.0% | 21/40 = 52.5% |
| 查询图检测失败 | 0/100 | 3/40 |
| 正确线索相似分中位数 | 0.9150 | 0.5273 |

库外猫组 C 中，**14/20 = 70.0%** 的查询至少出现一个得分 ≥0.45 的候选；另有 **2/20** 张检测失败。出现候选只表示系统把其他猫列为待核实线索，不能解释为“70% 被认成某一特定猫”。Top-1 的 Wilson 95% 区间分别为 **93.0%–99.5%**、**22.1%–50.5%**；库外误候选率的区间为 **48.1%–85.5%**。这些区间较宽，因为外部样本量有限。

**结果解释**：A 来自识别模型公开训练数据所包含的数据集，不能作为模型对全新猫的独立准确率。B 的来源未列在该模型卡的识别投影层训练数据中，但仍是同一喂食站的照片，拍摄会话是否重叠未得到标注。两组均不能代表真实“主人旧照与陌生人街头手机照”场景的成功率。两组结果与库外误候选应同时汇报。

## 三、网页现场演示

1. 打开 `http://127.0.0.1:5173/`，在“浏览信息”查看发现线索，点击“查看详细信息”查看地点、时间、电话和全部照片。
2. 登录后进入“匹配线索”。该页面固定为**丢猫用户查找发现线索**；清空地点、日期、毛色等选填条件，使图片参与全图库比对。
3. 上传本机 `dataset_cat50/testset/images/013-mr-butter_positive_top.jpg`。本次固定复测中正确线索 `hsc-lost-013-mr-butter` 排第 **1**，相似分 **0.6979**。
4. 再上传同一只猫的 `013-mr-butter_positive_front.jpg`。这张照片的最高相似分 **0.4232**，低于显示阈值，因此网页没有候选。这个例子说明视角变化会影响结果。
5. 上传库外猫 `047-mr-plump_unknown_top.jpg`。本次复测出现错误候选，最高分 **0.6439**。应解释为需要人工核对的误报，不应把候选当作认领结论。

第 3–5 步的图片属于固定测试清单，保留了成功、漏报和误报。若图库、模型、阈值或筛选条件改变，现场名次和分数可能变化；展示时以当次页面结果和重新运行的评测文件为准。演示结束后可向老师说明：系统已经实现动态入库与以图搜图，当前主要待解决的问题是跨拍摄场景的识别和库外误候选。
