## 主要设计约束

按当前本地演示要求，50 只 `Cat Individual Images` 已进入 `sighting` 业务表，各取 2 张封面照片并全量索引合格图片；`source_type=cat50_sample` 保留来源。统一地点上海市浦东新区、统一时间 2026-10-26 12:00 均为演示值。模型权重放 `models/`，数据放 `dataset_cat50/`，均不提交 Git。

已发布线索的快捷匹配默认同城，可手动扩大到全部城市；时间与距离只提供很小的排序加分。独立图片匹配允许上传 1–5 张查询照片，无需发布记录；城市、区县、日期范围、毛色、花纹、品种和体型用于限制候选范围，然后按图片相似分排序。每次查询仍做精确余弦扫描。发布时同步提取向量并保存记录，记录增加后必须改为异步任务和向量索引。ONNX 模型在发布时立即提取向量，失败会返回明确错误。更换权重或裁剪模型时，特征表的 `model_version` 不再匹配，新模型不会读取旧向量；后续需要批量重建命令。时间目前以用户本地输入的文本保存，尚未转换 UTC。

`/api/v2/browse` 默认显示全部活跃走失/发现记录，含标记为样例的 50 条走失记录，支持类型、城市、区县、毛色、花纹、品种、日期与分页。列表不含联系电话、用户 ID 或坐标；点击联系会通过单独接口直接返回电话。样例记录没有电话。历史记录若此前未保存号码，发布者需在“我的发布”中编辑补充。旧 `/api` 为历史演示接口，启动正式原型时必须设置 `BACKEND_ENABLE_LEGACY=0`。

## 建议的下一开发批次

1. 完成逐张猫图复核，标记同框、错标和连拍会话；采集获得明确授权的“主人旧照 ↔ 街拍”正负样本，冻结独立测试集。
2. 建立 PostgreSQL/pgvector 与 Alembic 迁移，把图像和向量拆成独立记录；补撤回操作、限流和审核日志。
3. 加 Redis worker 完成异步裁剪/嵌入/增量匹配与通知；为失败任务做重试和幂等。
4. 在真实样本上校准显示阈值，测报告级 Recall@5/10、无匹配误报率及 P95 延迟，再决定部署。
