## 主要设计约束

平台业务库初始为空。`Cat Individual Images` 是**个体识别训练/验证素材**，不会自动导入为虚构的寻猫线索；真实记录只能由用户发布。模型权重放 `models/`，数据放 `dataset_cat50/`，均不提交 Git。

当前搜索默认同城，用户可以手动扩大到全部城市；时间与距离只提供很小的排序加分，尚无时间范围和地理半径筛选。每次查询仍做精确余弦扫描。发布与匹配是同步操作，记录增加后必须改为异步任务和向量索引。ONNX 模型在发布时立即提取向量，失败会返回明确错误。更换权重或裁剪模型时，特征表的 `model_version` 不再匹配，新模型不会读取旧向量；后续需要批量重建命令。时间目前以用户本地输入的文本保存，尚未转换 UTC。

`/api/v2/browse` 默认合并真实线索和独立研究猫，支持类型、城市、区县、毛色、花纹、品种、日期与分页。列表不含联系电话、用户 ID 或坐标；点击联系会通过单独接口直接返回电话。历史记录若此前未保存号码，发布者需在“我的发布”中编辑补充。旧 `/api` 为历史演示接口，启动正式原型时必须设置 `BACKEND_ENABLE_LEGACY=0`。

## 建议的下一开发批次

1. 完成逐张猫图复核，标记同框、错标和连拍会话；采集获得明确授权的“主人旧照 ↔ 街拍”正负样本，冻结独立测试集。
2. 建立 PostgreSQL/pgvector 与 Alembic 迁移，把图像和向量拆成独立记录；补撤回操作、限流和审核日志。
3. 加 Redis worker 完成异步裁剪/嵌入/增量匹配与通知；为失败任务做重试和幂等。
4. 在真实样本上校准显示阈值，测报告级 Recall@5/10、无匹配误报率及 P95 延迟，再决定部署。
